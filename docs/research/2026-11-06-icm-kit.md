# ICM workspace kit and citation hook (2026-11-06)

## Question
A kit built in another AI session proposed reorganizing this repo as an **ICM workspace**
(Interpretable Context Methodology: numbered stage folders, each with a `CONTEXT.md` contract) and
adding a Claude Code hook that makes research answers cite sources. What should we take?

## What we found
- **The repo already follows ICM's core idea:** context in layers, loaded only when needed.
  `CLAUDE.md` is the map, `AGENTS.md` and `STATUS.md` say where we are, `docs/V1-SPEC.md` holds the
  step contracts, `docs/plan/` is reference only.
- **Merging the kit as written would hurt:** its `CLAUDE.md` replaces the one that loads the agent
  rules and the sanitize rules; its config files contradicted the plan (a different agent harness,
  Postgres on a NAS, daily automatic price refresh, checking for new models at every routing
  decision); and its decisions log, model guides, test prompts and stage folders duplicate files the
  repo already has (two sources of truth drift apart).
- **The hook was the right idea with real bugs.** Tested on 12 sample turns, 5 behaved wrongly:
  "Source code..." counted as a Sources heading; a pasted document didn't start a new turn; a skill
  loading mid-reply reset the turn; every MCP tool (even IDE diagnostics) counted as research; a
  helper agent's web research wasn't checked. Its Windows command used `%USERPROFILE%`, which neither
  Git Bash nor PowerShell (where Claude Code runs hooks) expands.

## Recommendation (taken)
- **Citation hook:** rewritten and tested (`tools/claude-hooks/require_citations.py`,
  `tests/test_require_citations.py`), installed globally for Stop and SubagentStop with one command
  that works on macOS and Windows: `uv run --quiet --no-project "$HOME/.claude/hooks/require_citations.py"`.
- **From ICM:** research notes (`docs/research/`), a glossary (`docs/GLOSSARY.md`), and the
  "operate" pattern for recurring checks: the check runs and writes a report, a person approves any change.
- **Not taken here:** the stage folders and config files. A blank ICM template is kept outside the
  repo for new projects with repeatable steps.
- **Would change our mind:** the repo growing several parallel workstreams that need their own
  contracts (for example, scout, pricing and ops all running on schedules).

## Where it landed
This note, `docs/research/`, `docs/GLOSSARY.md`, `tools/claude-hooks/`.
